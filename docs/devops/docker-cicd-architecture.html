Vet Agent Build — Docker & CI/CD Architecture

Containerized runtime and automated delivery pipeline review

Architecture Overview

The proposed architecture containerizes the Node.js/Express application and introduces a GitHub Actions-based CI/CD pipeline. The application image is built once, published to a container registry, and deployed to staging and production environments. Persistent clinic data lives on a host-mounted volume outside the container.

The application runs as a non-root user inside a minimal Node.js container. Clinic data is persisted on the host via a named volume so it survives container restarts and updates. API keys and other secrets are injected at runtime via environment variables.

4. Key Components

Application Container

  • Node.js LTS base image
  • Non-root user
  • Multi-stage or minimal production layer
  • Health check on /health

Container Registry

  • GitHub Container Registry (default)
  • Tags: commit SHA, branch, latest
  • Release tags produce semantic versions

Data Persistence

  • Named volume for agent-home/memory/
  • Backup runbook before deployments
  • Single-replica constraint documented

Secrets Management

  • GitHub Secrets for CI/CD
  • Runtime .env or orchestrator secrets
  • No secrets baked into image

5. Security & Operations Considerations

  • Non-root container: The application runs as an unprivileged user to limit blast radius if compromised.
  • Secret isolation: API keys are injected at runtime, not committed or built into images.
  • Data volume: Patient/visit JSON files live on the host via a volume, not inside the container layer.
  • Single-replica warning: The current JSON-file store is not safe for multi-replica deployments. Scale horizontally only after migrating to a real database.
  • Health checks: A /health endpoint lets orchestrators restart unhealthy containers.
  • Graceful shutdown: The app handles SIGTERM to close the HTTP server and flush in-flight writes.
